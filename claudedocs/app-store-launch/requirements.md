## 1. Hard blockers — cannot submit, or near-certain rejection

**B1. Privacy policy URL. — DONE, PR #60.** Published from this repo on GitHub
Pages rather than the site: `site/privacy/index.html` plus a
`.github/workflows/pages.yml` that deploys `site/` on pushes touching it. URL
will be `https://fontezbrooks.github.io/TheSouthernShmooze/privacy/`. Copy is
derived from the form schemas, the typed event map, and the edge functions, and
states the partial-lead save, the three-digit ZIP prefix, and the absence of an
advertising identifier. **Owner action after merge:** Settings → Pages → Source
= GitHub Actions, then confirm `hello@thesouthernshmooze.com` is the right
address for privacy requests.

**B2. App privacy label answers.** A draft exists at
`claudedocs/analytics/privacy-label.md` (written at analytics P3). It must be
re-checked against the events actually shipping in the launch build, then entered
in App Store Connect › App Privacy. Draft declares six collected types across
Contact Info, Identifiers, Usage Data, and Coarse Location, and zero tracking.

**B3. Privacy manifest contradicts the label. — DONE, PR #61.**
`ios.privacyManifests` now declares all eight collected types, each linked and
none tracking, with `NSPrivacyTracking: false`. The three required-reason API
entries are declared explicitly as well: a `prebuild --clean` starts from an
empty manifest and Expo's merge only preserves what it finds, so leaving them
implicit dropped them silently on the first regeneration.

**B4. Unused permission strings. — DONE, PR #61.** `expo-image-picker` and
`expo-document-picker` removed (zero call sites), taking the camera, microphone,
and photo-library usage strings with them. The four dead `@expo-google-fonts`
packages went in the same commit. Verified against a regenerated project: zero
`UsageDescription` keys.

**B5. Screenshots.** The 6.9-inch iPhone set is required. `supportsTablet` is
now `false` (PR #61, verified `TARGETED_DEVICE_FAMILY = "1"`), so no iPad set is
needed. Shot list in `metadata.md` §9. Capture from the launch build.

**B6. Regional content emptiness.** The registry is Middle-Tennessee businesses.
A reviewer searching from Cupertino may land on empty states and reject under
guideline 2.1 for incomplete content. Mitigate with App Store review notes that
name a working ZIP and walk the concierge and swipe flows.

**B7. Fresh production build + submit.** Cut from `main` after all code items
land. `eas.json` has `submit.production: {}` — the Apple ID, team, and ASC app
ID get supplied interactively or need adding.

Already satisfied, no action: export compliance
(`ITSAppUsesNonExemptEncryption: false`), 1024×1024 opaque app icon, no account
system so no account-deletion requirement.

## 2. Should fix before 1.0

**S1. Crash reporting via PostHog (D4).** Nothing reports a production crash
today; the only signal is a user complaining. Enable PostHog error tracking in
the existing `src/lib/analytics/` setup. No new vendor, so B1 and B2 are
unaffected. Verify captured exceptions carry no PII per the events.ts guard.

**S2. No error boundary, no `+not-found` route.** A JS exception yields a white
screen with no recovery path, and the registered `shmooze://` scheme means an
unknown deep link renders blank. Both are small additions to `app/_layout.tsx`.

**S3. EAS production environment is polluted.** `eas env:list production` on this
project returns variables belonging to a different app — Clerk, Convex, a Google
OAuth client id and **client secret**, and a guest code. Two of them are
`EXPO_PUBLIC_*`, which Expo inlines into this app's JS bundle. The Shmooze
Supabase and PostHog values are present and correct. Delete the foreign entries,
and rotate that Google client secret if it is live anywhere.

**S4. Device QA. — CLEARED by owner 2026-09-03.** Basic device testing is done;
the TestFlight build has active users. Remaining device work is narrower: a pass
on the launch build itself, since the picker removal, the iPad flip, and
`expo-updates` all change the binary. Worth one airplane-mode check too — every
repository collapses failures to a generic "Network error…" string.

**S5. Dynamic Type.** `Button.tsx` still uses fixed heights 56/48/32
(`:175/:180/:184/:190/:194`); labels clip at large accessibility text sizes. Same
class of defect Codex flagged on the hero CTA in PR #52. Not a rejection on its
own, an accessibility complaint waiting to happen.

**S6. App Store metadata copy. — DRAFTED, see `metadata.md`.** Name, subtitle,
promotional text, description, keywords, categories, the full age-rating
questionnaire, review notes, and a screenshot shot list. Every field has a draft
with its character count; the ones only the owner can answer are marked
**OWNER**. Two answers there deserve a read rather than a copy: unrestricted web
access and user-generated content, both of which turn on how the app behaves
today and change if reviews ship in 1.1.
